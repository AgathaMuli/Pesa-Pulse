# Day 1 – API Data Analysis Using Python Structures

A Jupyter notebook that pulls customer data from a public REST API, explores its nested JSON structure, flattens it into analysis-ready records, aggregates it with plain Python (loops, sets, dict comprehensions), then validates and visualises the results with pandas and matplotlib.

**Data source:** [JSONPlaceholder `/users`](https://jsonplaceholder.typicode.com/users) – a free fake API returning 10 sample user records.

---

## What the notebook does

| # | Step | Description |
|---|------|-------------|
| 1 | **Retrieve data** | `get_customers(url)` fetches the data with `requests`, using a 10-second timeout and graceful handling of network and JSON errors. |
| 2 | **Explore structure** | `explore(record)` recursively walks a nested record and prints every key with its Python type. |
| 3 | **Extract attributes** | `extract_attributes(customers)` flattens each customer into one dict (ID, name, username, email, email TLD, phone, city, zipcode, coordinates, company, website). |
| 4 | **Unique cities** | `unique_cities(customers)` uses a set comprehension to find distinct cities and compares that count to total customers. |
| 5 | **Aggregation in pure Python** | `city_counts()` counts customers per city using a loop; `email_domain_counts()` counts email TLDs using a dict comprehension. No `Counter`, no pandas. |
| 6 | **DataFrame** | Converts the flat records to a pandas DataFrame and checks that pandas' `value_counts()` matches the hand-written counts. |
| 7 | **CSV export** | Saves `customers.csv` and `city_counts.csv` to `output/`. |
| 8 | **Visualisation** | Saves a bar chart of customers by city and another by email TLD to `output/`. |

## Nested-Structure Path (Exploration)

The `explore()` function reveals that the JSON records are deeply nested. The deepest attribute we need to extract is the latitude/longitude, which is buried inside the address dictionary.

**Path to the deepest attribute:** 
`record` -> `address` (dict) -> `geo` (dict) -> `lat` (string) / `lng` (string)

*Assumption:* Because `lat` and `lng` are returned as strings by the API (e.g., `"-37.3159"`), the extraction function explicitly casts them to `float()`.

## Key findings

- **Geographic Dispersion:** Every customer lives in a different city. The unique city count is 10, matching the total customer count. This means the city chart is flat (every bar is 1), proving customers are highly dispersed geographically.
- **Email TLD Concentration:** When we group by Top-Level Domain (TLD) using `.split('.')[-1]`, we find that 3 out of 10 customers use `.biz` email addresses, while others are spread across `.tv`, `.info`, `.org`, etc.

### Which chart is more useful?
The **Email TLD chart** is significantly more useful for the marketing team. Because the geographic spread is completely uniform (every city has exactly one customer), the city chart does not highlight any regional clusters. The TLD chart, however, reveals a concentration of business-focused emails (`.biz`), which allows marketing to tailor B2B campaigns more effectively than a scattered regional campaign.
